BookVerse — Product Requirements Document

A digital archive for a reading life. Same design lineage as Kathak Journal — an illuminated manuscript, not a tracker.

1. Positioning

One line: BookVerse is not "what have you read" — it's "what has your reading life looked like."

Differentiator: the Reading Constellation (personal knowledge graph) — a visual map of how your books connect to each other through theme, genre, and your own notes. This is the one feature nothing else on the market does well. Everything else in this PRD exists to feed it data.

Explicit non-goals for v1: BookVerse v1 is not trying to be a social network, a gamification engine, or an AI chatbot. Those are v2+ if the core product earns them.

2. Critique summary (why the scope below differs from the original brainstorm)

Original idea Verdict Disposition
Full social layer (follows, feed, likes, comments) High backend cost, low differentiation vs. Goodreads Cut to v2
Achievements/gamification Fun but non-essential; no defined trigger mechanism Cut to v2, needs an eval strategy first
Generic "Ask AI" chatbot Bolted-on AI pattern, no real use case — and no LLM budget right now anyway Cut entirely for v1
Reading Journal (notes/quotes) Core differentiator's data source Keep, v1
Reading Analytics Genuinely useful, moderate cost Keep, v1, simplified
Personal Knowledge Graph Only truly novel idea in the concept Keep, v1 — as the spine, not a phase-4 add-on
Book discovery (search/trending) Necessary utility, not differentiation Keep, minimal

The rule going forward: a feature ships in v1 only if it either (a) feeds the Constellation, or (b) is required to use the product at all (auth, add-a-book, read-status). Everything else waits.

3. Design language — "The Illuminated Archive"

Directly continuing your existing dark-editorial identity (as used on your portfolio and Kathak Journal) rather than starting a new visual language from scratch. Same family, different manuscript.

Palette

Token Hex Use
--ink #1F1B18 Primary text, headers on light surfaces
--parchment #F6F1E7 Primary background (warm ivory, not stark white)
--parchment-dim #EDE6D6 Secondary surfaces, cards
--oxblood #6B1E2A Primary accent — CTAs, active states, progress fills (matches Kathak Journal's theme color exactly, ties the two projects visually)
--oxblood-deep #4A141C Hover/pressed states, dark-mode primary surface
--antique-gold #B08D57 Ratings, highlights, dividers, achievement/streak accents
--sage-muted #6E7A5E Optional tertiary — genre tags, secondary charts (keeps the palette from being only warm tones)
--charcoal #2B2521 Body text on parchment

Dark mode: invert to --oxblood-deep background, --parchment text, --antique-gold accents — same relationship as light mode, just at night.

Typography

  • Display / headings: Cormorant Garamond — same as your existing brand. Used for book titles, section headers, the hero line. Italic weight for pull-quotes from the Reading Journal.
  • UI / body: DM Sans — same as your existing brand. All buttons, nav, metadata, form fields.
  • Numerals (stats, streaks, page counts): DM Sans, tabular figures, slightly larger tracking — numbers should read as data, not decoration.

Motifs carried over from Kathak Journal

  • "Folio" language instead of generic SaaS nouns: a book's page is a folio, the journal entry is an inscription, the whole personal collection is a manuscript.
  • Illuminated corner flourishes / marginalia as subtle SVG accents on empty states and section dividers — never on every card (avoid the "gradient blob on every panel" trap the brainstorm doc itself warned against).
  • Roman-numeral or literary micro-copy in the footer (© MMXXVI), same as Kathak Journal, for brand continuity across your project suite.
  • Generous whitespace, serif-led hierarchy, restrained iconography — the anti-"purple gradient SaaS" direction you already committed to.

4. v1 Scope (the actual MVP)

4.1 Auth & Profile

  • Clerk (email + Google) — connected to Supabase via Clerk's third-party auth integration, not Supabase Auth
  • Minimal profile: name, avatar, bio, join date

4.2 Library

  • Add book via search (Google Books API, cached locally — see §6)
  • Status: Want to Read / Reading / Read / Paused / DNF
  • Progress tracking (page or %)
  • Custom shelves (user-created, many-to-many with books)

4.3 Reading Journal (data source for the Constellation)

  • Per-book: notes, quotes, tags, page references, start/finish dates
  • Tags are the raw material the Constellation graphs — make tagging fast and low-friction (autocomplete from prior tags, suggested tags from genre)

4.4 Reading Constellation (the differentiator)

  • v1 approach: not an LLM-embedding graph — no LLM credits budgeted right now, and it'd be too heavy for v1 anyway, hard to explain, hard to debug. Instead, nodes = books, edges = shared tags/genres weighted by count, plus manual "this reminded me of X" links the user can draw themselves.
  • Rendered as a force-directed graph (a JS library like d3-force is enough — no need for a custom physics engine)
  • This is intentionally simple in v1 so it ships; embedding-based similarity is a clean v2 upgrade path once real tag/note data exists to embed

4.5 Reading Analytics

  • Books/pages per month, average rating, genre breakdown, reading streak
  • Built directly off reading_sessions (see schema) — log this from day one, even in v1, or the analytics and streak features have nothing to compute from later

4.6 Discovery

  • Search (Google Books API)
  • Basic "similar books" via shared genre/tag — same underlying data as the Constellation, reused, not a separate system

Deliberately deferred to v2: social/follows/feed, achievements, AI chat, structured multi-axis reviews, public profile pages.

5. User story (single north star)

As a reader, I finish a book, write down what I thought and a quote that mattered, tag it, and later — without doing anything else — I can look at a map of my last twenty books and see the invisible thread connecting my "psychology" phase to my "fantasy" phase.

If a proposed feature doesn't serve this story, it's not v1.

6. Data model (Supabase / Postgres)

Refinements vs. the original brainstorm are marked (new).

-- Cached book metadata, so we don't hit Google Books on every render (new)
create table book_cache (
  id uuid primary key default gen_random_uuid(),
  source_id text unique not null,        -- Google Books volume id
  title text not null,
  author text,
  description text,
  isbn text,
  cover_url text,
  publication_date date,
  pages int,
  genres text[],
  cached_at timestamptz default now()
);

-- id is the Clerk user id (text, e.g. "user_2abc..."), not a Supabase Auth uuid
create table users (
  id text primary key,
  name text,
  bio text,
  avatar_url text,
  created_at timestamptz default now()
);

create table user_books (
  id uuid primary key default gen_random_uuid(),
  user_id text references users(id) on delete cascade,
  book_id uuid references book_cache(id),
  status text check (status in ('want','reading','read','paused','dnf')),
  progress numeric default 0,
  rating numeric,
  started_at date,
  finished_at date,
  unique (user_id, book_id)
);

create table journal_entries (
  id uuid primary key default gen_random_uuid(),
  user_id text references users(id) on delete cascade,
  book_id uuid references book_cache(id),
  content text,
  quote text,
  page_number int,
  tags text[],                          -- raw material for the Constellation
  created_at timestamptz default now()
);

create table shelves (
  id uuid primary key default gen_random_uuid(),
  user_id text references users(id) on delete cascade,
  name text not null,
  description text
);

create table shelf_books (
  shelf_id uuid references shelves(id) on delete cascade,
  book_id uuid references book_cache(id),
  primary key (shelf_id, book_id)
);

-- Session-level granularity from day one (new) — powers streaks + heatmap + pace
create table reading_sessions (
  id uuid primary key default gen_random_uuid(),
  user_id text references users(id) on delete cascade,
  book_id uuid references book_cache(id),
  pages_read int,
  duration_minutes int,
  session_date date not null default current_date
);

-- Manual "this reminded me of X" edges, plus computed tag-overlap edges (new)
create table book_connections (
  id uuid primary key default gen_random_uuid(),
  user_id text references users(id) on delete cascade,
  from_book_id uuid references book_cache(id),
  to_book_id uuid references book_cache(id),
  connection_type text check (connection_type in ('manual','shared_tag','shared_genre')),
  weight numeric default 1
);

create table goals (
  id uuid primary key default gen_random_uuid(),
  user_id text references users(id) on delete cascade,
  type text,
  target int,
  current int default 0,
  deadline date
);

RLS note (Clerk, not Supabase Auth): Supabase's native auth.uid() won't populate, since Clerk issues the JWT. Set Clerk up as a Supabase third-party auth provider, then write policies against (auth.jwt() ->> 'sub') = user_id instead — every table above needs this for select/insert/update/delete, except book_cache, which is shared read-only (all users hit the same cache) with writes restricted to a service role that populates it after Google Books calls.

Deferred tables (v2): follows, reviews (structured multi-axis), achievements, activity_feed.

7. Non-functional notes

  • API rate limits: always check book_cache before calling Google Books; only call the external API on a cache miss, then write the result back.
  • Streaks/heatmap correctness: compute from reading_sessions, never from user_books.finished_at alone — a single "finished" date can't reconstruct daily activity retroactively.
  • Constellation performance: compute book_connections edges on write (when a journal entry's tags change) rather than recomputing the whole graph on every page load.

8. Success metric for v1

Not "number of features shipped" — the metric is: can a user look at their own Constellation after ~15 logged books and immediately recognize a real pattern in their reading? If yes, the differentiator works and v2 investment (social, AI-assisted graph, achievements) is justified. If no, fix the Constellation before adding anything else.

Design system prime (paste first, before any screen prompt)

Design system: "The Illuminated Archive" — a literary, dark-editorial aesthetic for a
personal reading archive called BookVerse (sister product to a Kathak dance journal
with the same visual language).

Colors:
- Background (light): warm ivory parchment #F6F1E7, secondary surface #EDE6D6
- Background (dark): deep oxblood #4A141C
- Primary accent: oxblood #6B1E2A (buttons, progress bars, active states)
- Secondary accent: antique gold #B08D57 (ratings, highlights, dividers)
- Tertiary accent: muted sage #6E7A5E (tags, secondary chart series)
- Text: ink #1F1B18 on light surfaces, parchment #F6F1E7 on dark surfaces

Typography:
- Headings, book titles, pull-quotes: Cormorant Garamond (serif, literary, generous
  size, occasional italic for quotes)
- UI text, buttons, nav, metadata, numbers: DM Sans
- Numbers/stats use tabular figures and slightly wider letter spacing than body text

Visual motifs: illuminated-manuscript feel without being literally medieval — think
"a beautifully kept archive," not "fantasy game UI." Subtle corner-flourish or
marginalia-style SVG accents only on empty states and section dividers, never on
every card. Generous whitespace. Restrained, thin-line iconography. No purple
gradients, no glassmorphism, no generic "AI product" visual cliches. Terminology:
call a book's detail page a "Folio," a journal entry an "Inscription," the user's
whole collection their "Manuscript."
